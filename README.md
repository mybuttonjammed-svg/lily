# MemeCoin Pet — LILYGO T-Dongle-S3

A small Tamagotchi-style pet for the **LILYGO T-Dongle-S3 (ESP32-S3, ST7735 160x80 display)**. It fetches SOL/USD and the 24-hour change from CoinGecko, reacts with facial expressions and the APA102 RGB LED, and stores pet progress in ESP32 NVS flash.

## Features

- Pixel-style frog pet with happy, bullish, bearish, hungry, and sleepy moods
- Live SOL/USD price + 24-hour change (requests no more often than once per minute)
- APA102 RGB LED mood colors
- BOOT button: tap to feed (+10 XP, reduce hunger, increase happiness); hold for ~0.85 s to cycle Pet / Market / Stats pages
- Persistent XP, happiness, hunger, and feed count across power cycles
- Wi-Fi failure fallback: the pet remains usable offline and the price shows as unavailable

## Hardware confirmed

This project targets the **T-Dongle-S3**, not the similarly named T-Display-S3. It uses display pins CS=GPIO4, MOSI=GPIO3, SCLK=GPIO5, DC=GPIO2, RESET=GPIO1, backlight=GPIO38; APA102 LED data=GPIO40 and clock=GPIO39; BOOT=GPIO0. Check your board revision before flashing.

## Configure Wi-Fi

1. In the project folder, copy `include/secrets.example.h` to `include/secrets.h`.
2. Replace `YOUR_WIFI_NAME` and `YOUR_WIFI_PASSWORD` with your 2.4 GHz Wi-Fi credentials.
3. Keep `include/secrets.h` private; don't commit it to a public repository.

If you skip this, the pet still runs but remains offline.

## Build and upload (recommended fallback)

1. Install [Visual Studio Code](https://code.visualstudio.com/).
2. Install the **PlatformIO IDE** extension from the VS Code extensions panel.
3. Open this extracted `memecoin_pet` folder in VS Code.
4. Wait for PlatformIO to install the ESP32 platform and libraries from `platformio.ini`.
5. Connect the T-Dongle-S3 to USB. If it isn't detected, hold BOOT while plugging it in to enter download mode.
6. In PlatformIO, run **Build** (checkmark) and then **Upload** (right arrow). Select the detected serial port if prompted.
7. Unplug/replug the dongle normally. Do not hold BOOT during normal startup.

The project sets 16 MB flash, PSRAM disabled by implication, and USB CDC enabled. This project source has not been compiled on the target hardware in this environment; first build is the verification step.

## Browser-based installer

The `web-flasher/` folder contains an ESP Web Tools page and manifest **template**. A real one-click installer requires a compiled firmware binary hosted at a public HTTPS URL and the manifest's `path` updated to that exact URL. This chat environment does not have the ESP32 toolchain/network access needed to compile and test a binary, so no prebuilt binary is included and the web button is intentionally not presented as ready to flash.

To publish a working installer after building:

1. Build the firmware using PlatformIO.
2. Create a merged flash image for the ESP32-S3 using the bootloader/partition/app offsets generated by your build. Do not guess offsets; check PlatformIO's build output and the ESP32-S3 flash layout.
3. Upload the merged binary to the `web-flasher/firmware/` folder in a public GitHub repository.
4. Update `web-flasher/manifest.json` with the exact public HTTPS URL of that binary.
5. Publish the folder via GitHub Pages (Settings → Pages). The site must be HTTPS, and the firmware URL must be fetchable by the page (CORS enabled).
6. Open the published page in desktop Chrome or Edge, connect the dongle, and follow the install prompt.

ESP Web Tools docs: https://esphome.github.io/esp-web-tools/

## Controls

- **Tap BOOT:** feed the pet. Adds 10 XP and reduces hunger.
- **Hold BOOT ~0.85 seconds:** switch page (Pet → Market → Stats).
- **Stats:** shows level (XP/100 + 1), XP, feed count, happiness, and hunger.

## Notes

- Price API: CoinGecko's public simple-price endpoint. Rate limits/outages can cause temporary missing data.
- This is a toy/educational display, not trading or investment advice.
- TLS certificate validation is disabled for the public price request in this starter firmware to keep setup simple. For a public/production build, use certificate validation or a pinned CA certificate.
- NVS progress is stored locally on the ESP32. It is not written to the TF card.
